# Watch Out for Barnacles

_Last updated: 2025-12-16_

The barnacles metaphor describes how poor code attracts more poor code, creating layers of technical debt that become increasingly difficult to remove over time. Like barnacles accumulating on a ship's hull, bad code slows down development velocity and becomes entrenched in the system.

When teams take shortcuts or accept subpar code quality, it signals that the area is "okay" to be messy. This attracts more quick fixes and workarounds, compounding the problem. Eventually, simple cleaning tools no longer work - you need industrial-strength solutions and significant time investment.

A team burdened by barnacle-encrusted code cannot operate at top performance, just as a barnacle-covered boat experiences drag that slows its speed.

**Warning signs:**

- Areas of code that developers actively avoid working on
- Increasing time required for changes in specific modules
- Code quality degrading faster than it improves
- Technical debt accumulating in the same areas repeatedly
- Team velocity declining over time
