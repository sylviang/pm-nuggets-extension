# By Monkeys

_Last updated: 2025-12-16_

A cautionary metaphor derived from the infinite monkey theorem, warning against random, hypothesis-free experimentation. Just as a monkey randomly hitting keys might eventually type Shakespeare, a team running endless A/B tests without strategy might accidentally find wins - but at enormous waste.

The anti-pattern: treating your users as unpaid test subjects for every random idea, hoping something works. The reality: only 1 in 7 A/B tests succeeds on average. Random experimentation without insight wastes resources and delays real learning.

**Why it fails:**
- **No compounding knowledge**: Random tests don't build on each other or deepen understanding of user behavior
- **Low signal-to-noise**: Most experiments fail, and without hypotheses, you can't learn why
- **Opportunity cost**: Time spent on uninformed tests could be spent on insight-driven experiments with higher hit rates
- **User fatigue**: Constant changes confuse users and erode trust

**The alternative - Hypothesis-driven testing:**
Start with user research and data analysis to form clear hypotheses about what will work and why. Test to validate learning, not to hope for lucky breaks.

**Example**: Instead of testing 20 random button colors (monkey approach), analyze user session recordings to identify friction points, hypothesize that checkout anxiety drives abandonment, and test trust signals like security badges and money-back guarantees.
